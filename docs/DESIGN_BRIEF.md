# Study Alarm — Design Brief

> Claude Design / 디자인 작업용 브리프  
> 직장인이 업무 중 틈틈이 **한 문제씩** 푸는 데스크톱 공부 앱

---

## 1. 한 줄 컨셉

**일하다가도, 설정한 시간에 알림이 오면 → 창을 열어 → 객관식/주관식 한 문제를 풀고 → 바로 업무로 돌아간다.**

- 타깃: 직장인 (점심·근무 중 짧은 학습)
- 플랫폼: Windows / macOS 데스크톱 (Electron 껍데기 + 웹 UI)
- 톤: 집중을 방해하지 않는 **가볍고 빠른** UX. 무거운 LMS 느낌 지양

---

## 2. 제품 원칙

1. **한 번에 한 문제** — 알림 진입 시 장황한 홈이 아니라 문제(또는 아주 짧은 허브)로
2. **30초~2분 안에 끝낼 수 있는 밀도** — 스크롤·단계 최소화
3. **답은 바로, 설명은 선택** — “답안지 바로보기”로 갈라진 패널에서 확인
4. **설정은 단순** — 알람 구간 + 간격이 핵심
5. **진도는 한눈에** — 숫자·그래프보다 “오늘/이번 주 얼마나 했는지”가 우선

---

## 3. 기술 배경 (디자인 제약)

| 영역 | 방식 | 디자인에 미치는 영향 |
|------|------|----------------------|
| UI 전체 | Next.js → Vercel 배포 | 웹 UI처럼 그리면 됨. 반응형보다 **데스크톱 창** 우선 |
| 네이티브 | Electron (알림·스케줄만) | OS 알림 카드 문구/타이틀 고려. 앱 아이콘·트레이 아이콘 필요 |
| 업데이트 | 화면은 웹 배포로 갱신 | 앱 재설치 없이 UI 변경 가능 → 실험적 UI 가능 |
| 알림 스케줄 | **로컬 Electron** (서버 크론 없음) | “몇 시~몇 시, N분/시간마다” 설정을 유저가 앱에서 지정 |

**권장 창 크기 (초안, 디자인에서 조정 가능)**

- 기본: 960×720 내외
- 최소: 800×600 정도 (답안 스플릿 시에도 답/문제가 읽힐 것)
- 모바일 웹 대응은 **1차 범위 밖** (있어도 보너스)

## 4. 기본 기능 범위 (MVP)

### 4.1 설정 (Settings)

유저가 알람 정책을 정한다.

| 항목 | 설명 | UI 노트 |
|------|------|---------|
| 알람 ON/OFF | 전체 사용 여부 | 토글 |
| 시작 시각 | 예: 10:00 | 타임 피커 또는 시/분 선택 |
| 종료 시각 | 예: 18:00 | 시작 이후여야 함 (에러 상태 필요) |
| 간격 | N **분** 또는 N **시간** | 숫자 + 단위 셀렉트 |
| (선택) 평일만 | 월–금만 | 토글. 1차에 넣어도 됨 |
| 저장 | Electron에 스케줄 반영 | Primary 버튼. 저장 성공 피드백 |

**설정에 넣을 수 있는 부가 (1차 optional)**

- 관심 주제 / 과목 (나중에 문제 필터용)
- 알림 문구 미리보기

**설정에 넣지 않음 (1차 out)**

- 서버 푸시, 팀 공유, 소셜 로그인 복잡한 플로우 (계정은 추후)

---

### 4.2 알림 (Notification)

- **실행 주체:** Electron (OS 네이티브 알림)
- **트리거:** 설정한 시간대 안 + 간격 도래
- **유저 행동:** 알림 클릭 → 앱 창 포커스 → **문제 풀이 화면** (또는 `/question/next`)

**알림 카피 가이드 (초안)**

| 요소 | 예시 |
|------|------|
| Title | `한 문제 타임` / `Study Alarm` |
| Body | `지금 1문제만 풀어볼까요?` |
| (길게 쓰지 말 것) | 문제 전문은 알림에 넣지 않음 |

**디자인 산출물**

- 알림 문구 톤 가이드 (KR)
- 앱 아이콘 (알림·독·트레이용 심플 마크)
- 창이 백그라운드/최소화였다가 뜰 때의 “짧은 학습 모드” 첫 화면 상태

---

### 4.3 문제 풀이 (Question)

객관식·주관식 **둘 다** 지원.  
같은 레이아웃 뼈대를 쓰고, 입력 영역만 타입에 따라 바뀐다.

#### 공통 레이아웃

```
┌──────────────────────────────────────────────────────────┐
│  [과목/태그]          진도 미니     [답안지 바로보기]      │
├────────────────────────────┬─────────────────────────────┤
│                            │                             │
│  문제 영역                  │  답안지 패널 (토글 시)       │
│  - 문항 번호/난이도(opt)    │  - 정답                      │
│  - 본문                    │  - 해설                      │
│  - 입력 (객관/주관)         │  - (opt) 관련 개념           │
│  - 제출 / 다음             │                             │
│                            │                             │
└────────────────────────────┴─────────────────────────────┘
```

- **답안지 바로보기:** 화면이 **좌우(또는 상하)로 갈라지며** 답안 패널이 펼쳐짐
- 기본 상태: 답안 패널 **닫힘** (문제 풀이 집중)
- 다시 누르면 패널 닫힘 (토글)
- 제출 전에도 볼 수 있음 (학습용 — “커닝 방지”보다 **빠른 확인 학습**이 우선)
- 제출 후에는 정답/오답 하이라이트 + 답안 패널과 내용 정합

#### 객관식 (Multiple Choice)

- 선택지 2~5개 (보통 4)
- 한 개 선택 (1차: 단일 정답)
- 선택 후 **제출** → 정오 표시
- 선택지 상태: default / hover / selected / correct / incorrect

#### 주관식 (Short Answer)

- 단답 텍스트 입력 (한 줄 또는 짧은 멀티라인)
- placeholder 예: `답을 입력하세요`
- 제출 후 정답과 비교 결과 표시
  - 1차: 문자열 정규화 비교(대소문자·공백) 정도로 가정 — UI는 **맞음 / 다름 / 부분일치(opt)** 상태만 준비
- (opt) “비슷한 답도 인정” 배지는 나중에

#### 문제 풀이 CTA

| 버튼 | 역할 |
|------|------|
| 제출 | 채점 |
| 다음 문제 | 한 문제 더 (근무 중엔 안 눌러도 됨) |
| 닫기 / 나중에 | 창 숨김·트레이 (카피·위치 디자인) |
| 답안지 바로보기 | 스플릿 패널 토글 |

#### 상태 목록 (디자인 필수)

1. 로딩 (스켈레톤 — 흰 화면 정지 느낌 금지)
2. 풀이 중 (미제출)
3. 답안 패널 open / close
4. 제출 후 정답
5. 제출 후 오답
6. 에러 (문제 로드 실패)
7. 빈 상태 (더 이상 문제 없음)

---

### 4.4 진도 (Progress)

공부 기록을 **한눈에** 보는 화면.

**1차 필수 정보**

| 블록 | 내용 예시 |
|------|-----------|
| 오늘 | 푼 문제 수 / 정답률 |
| 이번 주 | 푼 문제 수 / 연속 학습 일수(streak) |
| 누적 | 총 푼 문제, 총 정답률 |
| 최근 기록 | 최근 N문제: 과목, 정오, 시각 |
| (opt) 과목별 | 태그별 푼 수·정답률 간단 바/리스트 |

**진도 화면에서 하지 않아도 되는 것 (1차)**

- 복잡한 차트 대시보드
- 리더보드 / 친구 비교
- PDF 리포트

**빈 상태:** 아직 푼 문제 없음 → “알림을 켜고 첫 문제를 기다려 보세요” + 설정으로 유도

## 5. 정보 구조 (IA) / 화면 목록

```
앱
├── 홈 (Hub) — optional short landing
│     · 다음 알람 요약
│     · “지금 한 문제” CTA
│     · 오늘 진도 미니
├── 문제 풀이 /question/[id] or /question/next
├── 진도 /progress
└── 설정 /settings
```

**글로벌 네비 (데스크톱)**

- 좌측 사이드바 **또는** 상단 탭: `홈` · `진도` · `설정`
- 문제 풀이 중에는 네비를 약하게 / 숨김 가능 (집중 모드)
- 알림으로 진입 시: **네비보다 문제 본문이 먼저** 보이게

## 6. 핵심 유저 플로우

### Flow A — 알림으로 한 문제

1. OS 알림 수신  
2. 클릭  
3. 앱 창 전면 → 문제 풀이 화면  
4. 풀기 → 제출 → (원하면) 답안 패널 / 다음  
5. 창 닫기 또는 트레이로 숨김 → 업무 복귀  

### Flow B — 설정 변경

1. 설정 진입  
2. 10:00–18:00, 30분 간격 등 입력  
3. 저장 → 성공 토스트/인라인 확인  
4. 이후부터 로컬 스케줄 반영  

### Flow C — 자발적 학습

1. 홈 또는 트레이에서 앱 열기  
2. “지금 한 문제”  
3. Flow A의 4–5와 동일  

### Flow D — 진도 확인

1. 진도 메뉴  
2. 오늘/주간/최근 기록 확인  
3. 최근 문항 클릭 시 해당 문제 복습(opt, 있으면 좋음)

## 7. 답안지 스플릿 UI 상세 요구

디자이너가 특히 집중할 파트.

| 항목 | 요구 |
|------|------|
| 트리거 | 헤더 우측 등 고정 위치 버튼 `답안지 바로보기` |
| 동작 | 클릭 시 콘텐츠 영역이 **스플릿** (권장: 좌 문제 / 우 답안) |
| 비율 | 기본 50:50, 최소 문제 영역이 너무 좁아지지 않게 (예: 40:60~60:40) |
| 애니메이션 | 짧고 가볍게 (200–300ms). 과장된 페이지 전환 X |
| 좁은 창 | 창 너비가 부족하면 **하단 드로어/오버레이** 폴백 허용 |
| 내용 | 정답 강조 + 해설 본문. 코드/수식 가능성 있는 타이포 여유 |
| 접근성 | 버튼 토글 상태(펼침/접힘) 시각적으로 구분 |

**카피 후보**

- `답안지 바로보기` / `답안 닫기`
- `정답 보기` (더 짧을 때)

## 8. 콘텐츠 톤 & 카피 방향

- 존댓말 또는 부드러운 반말 중 **하나 통일** (추천: 짧고 담백한 존댓말)
- 죄책감·잔소리 톤 금지 (“또 미루셨네요” X)
- 짧고 행동 유도: “한 문제만”, “저장됐어요”, “다음에 이어서”

| 상황 | 카피 예 |
|------|---------|
| 알림 | 지금 1문제만 풀어볼까요? |
| 정답 | 맞았어요 |
| 오답 | 아쉬워요. 답안을 확인해 보세요 |
| 설정 저장 | 알람 설정을 저장했어요 |
| 문제 없음 | 준비된 문제가 없어요 |

---

## 9. 비주얼 방향 (가이드, 확정 전)

- **키워드:** calm, focused, light productivity, study-not-school
- **피하기:** 어린이 학습지, 게임화 과다(폭죽·뱃지 남발), 기업용 무거운 admin
- **컬러:** 중성 배경 + 포인트 1색 (집중 방해 최소). 정답=그린, 오답=레드 계열 시맨틱
- **타이포:** 본문 가독성 우선. 문제는 약간 큰 본문 사이즈
- **다크 모드:** 1차 optional. 가능하면 라이트 먼저, 토큰만 다크 확장 가능하게

## 13. 구현 메모 (개발 정렬용, 디자인 참고)

```
apps/web (Next.js on Vercel)  → 모든 화면
apps/desktop (Electron)       → 알림 + 로컬 스케줄 + Vercel URL 로드
```

- 설정 저장 시 웹 → Electron bridge → 로컬 스케줄 재등록
- 알림 클릭 → 웹의 문제 풀이 라우트로 진입
- 화면 업데이트는 Vercel 배포로 반영 (유저 앱 재다운 최소화)

---

## 14. 결정이 필요한 디자인 질문 (작업 시 제안 환영)

1. 홈을 둘지, 알림 진입은 무조건 문제 직행인지  
2. 답안 스플릿 방향: 좌우 vs 하단 시트 기본값  
3. 제출 전 답안 공개를 강조할지, 보조 액션으로 둘지  
4. 브랜드명 / 앱 이름 확정 (가칭: Study Alarm)
